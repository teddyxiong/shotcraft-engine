# 滚动截图拼接最小修复设计

## 目标和范围

先解决连续屏幕截图无法拼接的问题。输出保留输入截图的完整宽度，正文接缝不能缺行或重复。
本轮不接入 pluely14，不增加 Tauri、后台开始/停止、显示器自动选择或 Base64 接口。
保留现有 `Stitcher::push`、`Push`、预览及最终图接口；不引入依赖或第二套拼接器。

## 已有证据

- 交接中的 Chrome 实验只有首帧成功，缺少原始输入帧，首次失败原因仍未确认。
- 当前整行 RGBA 哈希匹配要求行内所有像素完全一致。
- 临时实验使用相同正文和已知 37 像素位移：整幅滚动得到 `Appended(37)`，左侧 25% 固定时得到 `NoMatch`。
- `cargo test -p shotcraft-doc stitch --locked --offline`：现有 5 个测试全部通过；未覆盖固定侧栏。
- 上述实验只证明算法限制，不能当作历史 Chrome 故障的根因或真实场景验收结果。

## 方案比较

| 方案 | 代价和局限 |
|---|---|
| 仅补输入和评分诊断 | 可定位真实失败原因；本身不修复已复现的算法限制 |
| 先补诊断，再局部替换匹配核心（用户已确认） | 沿用现有输出逻辑，参考 LiteSnap 的匹配思路；可将改动限定在当前问题 |
| 搬入 LiteSnap 整个滚动会话 | 同时带入采集、队列、预览、滚动条估算等行为，超出本轮范围，不采用 |

## 推荐方案的实施顺序

1. 在现有采集路径增加可选诊断：只保存首个成功帧及首个失败帧，记录目标显示器、原始和裁剪后尺寸；图片留在本地临时目录，不提交。
2. 在匹配处记录实际拒绝原因及最佳候选位移、有效样本和评分；失败候选也要能观察。
3. 用真实帧核对内容、尺寸和重叠。若采集输入错误，先修复该原因，再判断匹配改动。
4. 针对确认的匹配限制，在 `crates/doc/src/stitch.rs` 内实现必要的匹配核心：
   - 根据同位置像素变化选取参与匹配的列，减少固定侧栏干扰；这不裁剪输出。
   - 用有纹理的局部特征提出垂直位移，再检查更广的重叠区域和文字、边缘细节。
   - 用像素差异衡量候选，避免整行中少量变化使重叠全部失效；仅匹配白底不构成可靠位移证据。
   - 保留固定头尾及高度限制的现有语义；向下追加完整宽度的新内容。
   - 未证明位移时保留最后成功拼接的基准，不能直接将失败帧变成新基准而丢失距离。
5. 回放相同真实帧，检查位移、输出高度和接缝，再由操作者准备 Chrome/GitHub 页面进行真实滚动验收。

参考的是 LiteSnap 的 Rust 原生实现，而非遗留的 TypeScript 拼接器：
<https://github.com/HuibingLin/LiteSnap/blob/fb0cc8f6d79ec747bdf1862c7093ec9986bcba0d/app/src-tauri/src/lib.rs#L596>。
仅参考算法思路，独立实现本轮所需部分，不复制其产品代码或资产。

## 验证和完成条件

- 优先运行现有 5 个拼接测试；如修改行为，仅增加一个覆盖固定侧栏的主路径回归测试，必要时一个关键误匹配拒绝测试。
- 不增加测试框架、依赖、快照或跨平台测试套件。
- 真实全屏帧内容、尺寸和重叠已核对；输出宽度与输入相同。
- 真实 Chrome/GitHub 向下滚动能持续追加；检查接缝没有明显缺行、重复或断裂。
- 若采集面板进入画面而妨碍验证，明确记录这个限制，不把合成图通过写成全屏实测成功。
- 本轮不自动启动截图、移动鼠标或重置权限；由操作者准备页面后进行采集。
- 未取得真实帧和实际滚动验收前，目标保持未完成。
